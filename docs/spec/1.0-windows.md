## Problem Statement
A non-technical person has a file in the wrong format: a photo that a website refuses, a spreadsheet that must become CSV, a Markdown note that must become a web page. The usual answers are online converters, which means uploading private files to a stranger's server, or heavy desktop programs full of options. They want to drop the file, check the target and get the result, and they want to be sure that the file did not leave their PC and that a damaged or hostile file cannot harm it.

## Solution
Kalei 1.0 is a small Windows app with one window. The user drops files or folders (or presses Choose files), checks the proposed target Format and presses Convert. The window takes the colour of what was dropped. Dragging files over the window also opens the **In-app Donut**: a ring of target Formats at the cursor; releasing on one converts at once. All parsing of the files happens in a sandboxed Worker with no network, nothing is uploaded, nothing is sent, and the original files are never touched. 1.0 ships the built-in Modules for images, data and text, in English and Italian.

## User Stories

### Dropping and converting
1. As a user, I want to drop one file on the window, so that I can convert it without learning an interface.
2. As a user, I want a Choose files button, so that I can pick files when I cannot drag.
3. As a user, I want Kalei to recognise the real type of my file from its content, so that a wrongly named file still converts.
4. As a user, I want a notice when the extension says one thing and the content another ("This looks like PNG, not JPG"), so that I understand what Kalei will do.
5. As a user, I want only sensible target Formats offered, with the most common one preselected, so that I can convert in three actions.
6. As a user, I want to see the real file name, detected Format and size on a file card, so that I know it is the right file.
7. As a user, I want the window and icon to take the colour of the file's Category, so that I get immediate visual confirmation.
8. As a user, I want a progress bar and a Cancel button during a conversion, so that I stay in control.
9. As a user, I want to see the output name and real size when the conversion is done, so that I can check the result.
10. As a user, I want Show in folder and Convert another after a conversion, so that I can continue quickly.
11. As a user, I want my original file never to change, move or disappear, so that I can try conversions without fear.

### The Donut
12. As a user, I want a ring of target Formats to open at my cursor when I drag files over the window, so that I can convert with one gesture.
13. As a user, I want the Format under the cursor to light up, so that I know what I am about to choose.
14. As a user, I want releasing on a Slice to start the conversion with no further window, so that the gesture is complete.
15. As a user, I want releasing outside the Slices to give me the normal drop flow, so that I never lose my drop.
16. As a user, I want a way to close the Donut without choosing (move away, press Esc), so that a mistaken drag costs nothing.
17. As a user who cannot use a mouse, I want the same Format list in the main window with full keyboard and screen-reader operation, so that the Donut is never the only way.
18. As a user with "Reduce animations" on, I want the Donut to appear without motion, so that it is comfortable.
19. As a user, I want to see "analysing" when Kalei does not yet know the files, so that I understand a short wait.
20. As a user dragging files of different kinds, I want the Donut to offer only the Formats valid for all of them, so that I cannot pick something impossible.

### Batches and folders
21. As a user, I want to drop many files at once, so that I convert a whole set in one go.
22. As a user, I want to drop a folder, so that everything inside is found, in subfolders too.
23. As a user, I want one target Format for the whole Batch in 1.0, so that the choice stays simple.
24. As a user dropping files with no common target, I want the message "These files have no format in common. Convert them in separate groups.", so that I know what to do.
25. As a user, I want each file in a Batch to show its own status (queued, converting, done, error, skipped), so that I can follow it.
26. As a user, I want to see why a file was skipped, so that I do not wonder.
27. As a user, I want a failure of one file not to stop the others, so that a Batch finishes what it can.
28. As a user, I want Cancel all and Retry failed, so that I can recover from interruptions.
29. As a user, I want large Batches to stay responsive, so that 10,000 files do not freeze the window.

### Options and output
30. As a user, I want to change quality or size only in an Advanced panel, so that defaults stay simple.
31. As a user, I want only the options that make sense for my pair, and a Reset to defaults, so that I am not overwhelmed.
32. As a user, I want my photos' GPS location removed by default, so that I do not leak where I was.
33. As a user, I want the photo's orientation applied to the pixels, so that converted photos are not rotated.
34. As a user, I want an option to strip all metadata, so that I can remove it completely.
35. As a user, I want the output next to the original by default, or in a folder I choose, so that I find it.
36. As a user, I want a clash never to overwrite anything and the new file to be named `name (1).ext`, so that nothing is lost.
37. As a user, I want to choose "ask every time" with "apply to all" for clashes, so that I decide when I care.
38. As a user converting CSV, I want the separator, encoding and decimal commas understood automatically and overridable, so that Italian files come out right.
39. As a user converting JSON to a table, I want nested values flattened predictably, so that the result is usable.

### Errors and safety
40. As a user, I want clear errors that say what happened and what to do ("The file is damaged. Try another copy."), so that I can act.
41. As a user, I want a damaged, oversized or hostile file to fail cleanly, with no partial output left behind, so that nothing breaks my folder.
42. As a user, I want a file that is too big to say so and tell me where the limit is, so that I can change it if I want.
43. As a user, I want Kalei not to touch the network, so that my files stay on my PC.
44. As a user, I want to be sure that a converted spreadsheet never carries formulas I did not write, and that CSV cells cannot run as formulas when opened in a spreadsheet program, so that opening the result is safe.
45. As a user, I want HTML produced from Markdown to contain no remote resources and no scripts, so that opening it leaks nothing.
46. As a user, I want Open log folder to show logs that contain no file names or paths, so that I can send them to support without exposing anything.
47. As a user, I want to be told when HEIC cannot be read because my Windows lacks the needed extension, so that I know what to install.

### Preview and browser
48. As a user, I want a preview of my file (a thumbnail, or the first lines of text), so that I am sure it is the right one.
49. As a user, I want the preview generated safely, so that a hostile image cannot attack the app through the preview.
50. As a user, I want to drag a file out of my browser and have it convert, so that I do not need to save it first.
51. As a user, I want Kalei to refuse a dragged link with "Save the file first", so that it never downloads anything on its own.
52. As a user, I want the converted file to keep its "downloaded from the internet" mark without the source address, so that Windows still treats it carefully and my history stays private.

### Settings, language and accessibility
53. As a user, I want the app in English or Italian, following Windows by default, so that I use my language.
54. As a user, I want light or dark theme following Windows, with an override, so that it suits me.
55. As a user, I want to turn the colour transition off, so that colour changes are instant.
56. As a user, I want to change the limits in Settings → Limits, so that I can adjust them to my PC.
57. As a user, I want to open the Releases page from Settings to check for updates myself, so that nothing updates silently.
58. As a user of a screen reader, I want names for the Drop zone, states and progress, so that I know what is happening.
59. As a keyboard user, I want every action reachable and visible focus, so that I never need a mouse.
60. As a user with colour-vision deficiency, I want the Category name and icon always shown, so that colour is never the only signal.

### Installation
61. As a user, I want a per-user installer that needs no administrator rights, so that I can install on my own.
62. As a user, I want a portable ZIP, so that I can run Kalei from a folder or a stick.
63. As a user, I want to download SHA-256 sums with each release, so that I can check what I downloaded.
64. As a user, I want to see every third-party licence in About, so that I know what is inside.
65. As a user, I want to uninstall cleanly, with my settings kept unless I choose otherwise, so that nothing is left behind by surprise.

## Implementation Decisions

### Components and responsibilities
- **App** (UI only): window states, Drop zone, accent and theme, Settings, In-app Donut host, accessibility. It never decodes untrusted content.
- **Core** (no UI, no OS API): header-stage detection, queue, Limits, Broker, output naming, temporary-file and log policy, settings, and the Module manager that reads the built-in manifests through the same loader as Optional ones will use in 1.1.
- **Platform adapters**, Windows implementations in 1.0: sandbox launcher (Job Object + AppContainer without network), system image codec (WIC), paths, file origin (origin mark), installer layout (install and portable data locations). The global pointer hook and shell integration have their interfaces and no implementation until 1.2 and 1.1.
- **Worker executable** hosting the three built-in Modules (images, data, text), started once per Conversion, talking to the Core by the IPC of [ipc-spec](../ipc-spec.md).
- **Donut** library, free of UI and OS code; the Avalonia control and the in-app host sit on top of it.

### Formats and behaviours
- **Images**: PNG, JPG, WebP, GIF, BMP, TIFF, ICO, AVIF as sources and targets, HEIC as source only, **limited to the confirmed set** from the spike. Animated inputs convert their first frame, shown as a note. Transparency going to JPG or BMP is flattened onto white. ICO output has 16, 32, 48 and 256 px images (never upscaled; larger inputs scaled down); as an input the largest image is used. GPS is removed by default, orientation applied to pixels, options: quality, maximum size, strip all metadata. Untrusted loaders and the SVG loader are disabled.
- **Data**: CSV, TSV, XLSX (spreadsheet) convert among themselves; JSON, YAML, XML (document) convert among themselves; JSON converts to and from CSV, TSV and XLSX (JSON must be an array of objects when going to a table; nested values are flattened with dot notation, arrays as `a.0`, `a.1` or joined with a configurable separator; an array of plain values becomes one column named `value`; ragged objects give the union of keys with empty cells). Separator (`,` `;` tab) and encoding (UTF-8 with or without BOM, Windows-1252) are detected and overridable; Italian numbers (`1.234,56`) are understood; XLSX uses the first sheet unless "all sheets" is chosen (one CSV per sheet); formulas are exported as their cached value; nothing is ever written as a formula (S9). XML uses `@attribute` and `#text`, with DTD and external entities rejected.
- **Text**: TXT converts only to TXT (re-encoding and line endings). MD converts to TXT and to HTML; HTML converts to TXT and to MD. HTML output is a full page with minimal style, sanitised, with the Content-Security-Policy of S9.
- **Preselected target** (the most common): PNG, JPG, GIF, BMP, TIFF, ICO and AVIF → WebP; WebP → PNG; HEIC → JPG; CSV → XLSX; TSV → CSV; XLSX → CSV; JSON → YAML; YAML → JSON; XML → JSON; MD → HTML; HTML → MD; TXT → TXT.
- **Donut faces** follow the [design brief](../design-brief.md#donut-faces): all targets on the front Face in 1.0 (there is no back Face), source Format excluded.
- **Category** of each Format as in the matrix: images → image; CSV, TSV, XLSX → spreadsheet; JSON, YAML, XML, TXT, MD, HTML → document; unrecognised → other.

### Conversion and Batch behaviour
- Lifecycle as in [architecture](../architecture.md#conversion-lifecycle): header detection in the Core (at most 64 KB), Probe in a Worker where more is needed, Limits check, Broker opens handles, launcher starts the Worker under the sandbox, the Output is created exclusively under a reserved temporary name and renamed without replacing, partial files are removed on cancel, error or timeout, and the journal clears leftovers after a crash.
- A Batch has one target Format. With several Categories the offered targets are those valid for every file; with none, the Batch state shows the "separate groups" message and nothing starts. Skipped reasons: unsupported format, over a limit, system or hidden file, link, unreadable, clash declined.
- Parallel Workers follow the Limits table (cores ÷ 2, at most 4, within the memory budget). Large result lists are virtualised.
- Collisions: automatic `name (n).ext` by default; "ask every time" shows Keep both or Skip with "Apply to all"; Replace is never offered.
- Cancel kills the Worker and removes the partial Output; a Worker that stops answering for 5 s is killed by the watchdog.

### Limits and errors
Values are those of the Limits table in [architecture](../architecture.md#limits); the editable ones are shown in Settings → Limits with a hard upper bound. Every error has a code from [ipc-spec](../ipc-spec.md#error-codes) and one plain message in each language; no message contains a path or file name.

### Security mapping (1.0)
S1, S2, S3, S4, S5 (release gate), S6, S7, S9, S10 and S12 apply in 1.0. S8 (module integrity) starts with the first Optional module in 1.1; S11 (hook) starts in 1.2. If the sandbox cannot block the network on an OS tested in Ticket 0, the "no network" promise is removed from README and PRD for that OS.

### Accessibility and design
Layout A "Quiet", tokens and contrast from the [design brief](../design-brief.md). Full keyboard operation, visible focus, screen-reader names, WCAG AA contrast in both themes, Windows "Reduce animations" and Kalei's "Colour transition" switch (the stricter wins).

### Settings, localisation, logs, release
As specified in [settings.md](settings.md) and [release-pipeline.md](release-pipeline.md).

## Testing Decisions
- **What makes a good test**: it checks behaviour seen from outside (the Output produced, the error code, the files left on disk, the messages) and not internal structure. Every Format has samples: valid, truncated, with the wrong extension, and a large generated one (not committed). Tests check both the result and the failure.
- **Seams** (three, because security, formats and the Donut have different boundaries):
  1. **Core pipeline through the sandbox-launcher interface**: a fake launcher tests queue, naming, Limits, cancellation, journal and crash recovery fast; the real launcher tests the S5 gate (a TCP connect and a DNS lookup from inside a Worker must fail) and the format cases end to end.
  2. **Worker IPC boundary**: send `Convert` with handles, assert the Output file and the reply; one test per supported pair.
  3. **Donut library**: pure tests of geometry, hit-testing, Faces and format intersection.
  The thin UI is checked by hand and with headless tests where Avalonia allows.
- **Test first** (`/tdd`) for Core, Worker and Donut. Logs are scanned for sample paths (S10). The gate and the performance thresholds are measured on the Hyper-V reference machine and the Windows 11 PC ([ticket-0](../ticket-0.md#reference-machines)).
- **Prior art**: none in this repository yet (no code exists); the first tickets create the pattern, and later ones follow it.

## Out of Scope
Everything listed as out of scope or later in the [PRD](../PRD.md): Optional-module installation, per-Category targets in a Batch, Explorer menu, command line, recent conversions (1.1); Linux and macOS (1.x); Global Donut, Sentinel, resident process (1.2); size Estimate; automatic updates or update checks; cloud features; editing, OCR, renaming, crop, watched folders.
